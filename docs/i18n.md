# Languages

Aidline shows its interface in English, French and Spanish. The reader picks a language in the header, and the choice is saved in the browser (`aidline_locale`). With no saved choice, the first language the browser asks for that Aidline supports is used, then English.

There is no i18n library. The pieces are small enough to read in one sitting:

| File                                        | Role                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------------------ |
| `src/i18n/messages.ts`                      | Every message, in `en`, `fr` and `es`                                          |
| `src/i18n/index.ts`                         | Language list, choosing a language, `translate` and `translatePlural`          |
| `src/components/i18n/I18nProvider.tsx`      | Holds the current language, saves it, sets `<html lang>`, provides `useI18n()` |
| `src/components/i18n/T.tsx`                 | `<T k="…" />` and `<TPlural base="…" count={n} />` for server components       |
| `src/components/i18n/LanguageSwitcher.tsx`  | The language picker                                                            |

## What is and is not translated

Campaign content is never translated. Titles, summaries, descriptions, locations and organiser names are shown in the language their author wrote them in. Only the interface around them changes.

Translated so far: the header and navigation, the footer, the wallet menu, the campaign card, the transaction stepper, the "you backed this" mark and the verifier queue.

Still English, and to be moved onto messages page by page: the home page, the campaigns list and detail pages, the start form, the verifiers and admin pages, the donate, refund, release and cancel panels, the how it works page, error pages, the chart and the Storybook stories. The campaign type labels ("Emergency", "Climate") come from `src/components/campaign/kind.ts` and are also still English.

## Adding or changing text

1. Add the key to `en` in `src/i18n/messages.ts`, then to `fr` and `es`. A missing key in `fr` or `es` is a type error, and `npm test` also checks that every language has the same keys and the same `{placeholders}`.
2. In a client component, use `const { t } = useI18n()` and `t('your.key', { name })`. In a server component, use `<T k="your.key" vars={{ name }} />`.
3. For a count, add `your.key.one` and `your.key.other` and use `tn('your.key', n)` or `<TPlural base="your.key" count={n} />`. The right form is chosen with `Intl.PluralRules`, so French treats zero as singular.
4. Write the copy by the voice rules in [DESIGN.md](../DESIGN.md): plain and specific, sentence case, no exclamation marks, no emoji. A test fails if a message contains `!` or an emoji.

## Adding a language

Add its code to `LOCALES`, a name written in that language to `LOCALE_NAME` and an `Intl` tag to `INTL_TAG` in `src/i18n/index.ts`, then add a full catalogue to `messages.ts` and register it in `catalogs`. The compiler and `test/i18n.test.ts` list anything missing.

## Known limits

- The page is rendered in English first and switches to the saved language straight after it loads, so a French or Spanish reader sees a brief flash of English. Removing it means choosing the language on the server (a cookie and a `[locale]` route), which would make every page dynamic, so it is left for a decision by the maintainers.
- Dates in the deadline label follow the chosen language. Amounts and the local currency estimate do not yet.
